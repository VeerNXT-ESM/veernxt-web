# Book Cover Studio — Handover (2026-10-13)

Written for: Shreya, who will take the Book Cover Studio forward.

## What it is

A CMS tool that builds a book's **cover, spine and angled 3D thumbnail** from editable fields, so the content team no longer has to generate covers with GPT. A typo is fixed by editing the text and saving again. Nothing is regenerated by an AI model.

- **Where:** Admin → Learning → **Book Covers** (`/admin/book-covers`), or the **Design cover** button on any row in **Book Content** (opens `/admin/book-covers?resourceId=…`).
- **Status:** first version, pushed for the content team to review. Not yet confirmed against real books at scale.

## How to use it

1. Book Content → click **Design cover** on a book.
2. Fill in the fields on the left; the flat cover updates live, and the 3D thumbnail follows about half a second later.
3. **Save to book** uploads the images to R2, stores the data in Supabase, and sets that book's thumbnail.

Opened directly (no `resourceId`) the page is a scratchpad: edits are kept as a browser draft and there is no save button.

### Fields

| Area | What the team edits |
|---|---|
| Subject name | One line per row. Auto-sizes to fit the cover. |
| Type / badge | Guide or Precis; the badge text ("COMPLETE GUIDE") is editable. |
| Brand name | Defaults to `VEERNXT`; used on the cover and the spine. |
| Exams | "For" label plus one exam line per row (top-right panel). |
| Subjects | Up to 7, each with a label and an icon (20 icons available). |
| Bullets | One per line, up to 8. |
| Picture | Upload, height and focus sliders, fade under the text. |
| Logo | Defaults to the VeerNXT logo; a custom logo can be uploaded. |
| Colours | Paper, text/green, gold. |
| Text size & spacing | Sliders and number boxes for every block (see below). |
| 3D settings | Book angle, spine thickness (15–35%, default 35%), background. |
| Spine | Name size (0 = auto), logo size, optional Guide/Precis text. |

The spine shows only the subject name by default and fits it to the available height.

## How it works

Two layers, kept deliberately separate:

1. **Flat templates** (`BookCoverTemplate.jsx`, `.css`): React/HTML laid out on a fixed 1000×1480 canvas (spine 150×1480). The cover is a vertical flow (header → name → badge → subjects → bullets) with the picture behind it, so a bigger font or gap pushes the blocks below it down instead of overlapping them.
2. **Perspective compositor** (`src/lib/bookPerspective.js`): rasterises the flat cover and spine with `html-to-image`, then draws each face as 1-pixel-wide strips scaled by depth. That gives a correct perspective for a book turned about the vertical axis, with a hinge groove, a sheen, spine shading and a ground shadow. The live preview and the saved thumbnail use the same code, so they match.

The perspective is **rotation about the vertical axis only**. There is no top-edge tilt, and the right-hand page block is not visible.

## Where the data lives

**Supabase table `book_covers`** (`sql/book_covers.sql`, already run on production on 2026-10-12):

- Key `book_key`: `Guide::<lowercased title>` / `Precis::<lowercased title>` (the same title grouping Book Content uses), or `Intro::<resource_id>` for Intro.
- `cover_data` (jsonb): all text fields, topics, colours, layout sliders. The pictures are not stored here.
- `logo_url`, `image_url`, `thumb_url`, `flat_url`: R2 URLs.
- Public read; writes go only through the server (service role).

**R2**, under `book-covers/<slug>/`: `image-*`, `logo-*`, `thumb-3d-*.webp` (768×1152, transparent), `cover-flat-*.webp`. Hero picture and logo are re-uploaded only when they change.

**`resources.thumbnail_url`**: Save also writes the 3D thumbnail URL onto every `resources` row of that book.

**Server:** two actions in `api/admin/save-resource.js`: `book-cover-get` (loads the cover; fetches the R2 images server-side and returns them as data URLs so the bucket needs no CORS) and `book-cover-save` (upserts the row and updates `resources.thumbnail_url`). Both use the admin secret header like the other `books-*` actions.

## Known limits and open items

1. **Nothing uses the thumbnail on the learning pages yet.** Saving sets `resources.thumbnail_url`, but no Learning Center page reads it for books. Wire the book tiles to `book_covers.thumb_url` (or `resources.thumbnail_url`) to make it visible to learners.
2. **Renaming a Guide or Precis orphans its saved cover**, because the key includes the title. Fix: re-key `book_covers` inside the rename action in `save-resource.js`.
3. **Exams are typed by hand.** Prefilling them from the book's linked exams is straightforward but needs a look at the `lc_exam_resource_map` / `lc_exams` link tables first.
4. **No overflow warning.** Long titles, many bullets or big fonts can push the bottom of the cover past the edge. A check that warns when the flow height exceeds 1480 would help.
5. **The cover-picture library is manual.** Each book needs its picture uploaded. Reusing one picture per subject (for example "Computer Science") would save time and keep covers consistent.
6. **Fonts** (Outfit, Playfair Display) load from Google Fonts. If they fail to load, the baked image falls back to a system font. Self-hosting them would make thumbnails deterministic.
7. **Perspective** is vertical-axis only; a small top tilt and a visible page block would make it closer to the original GPT cover.
8. **Preview speed:** the live 3D preview re-rasterises on every edit (debounced about 450 ms). Fine for now; watch it on slower machines.
9. **Brand text:** the logo already contains the "From Service to a Prosperous Tomorrow" ribbon, and the cover also prints the tagline beside it. The team should decide whether to keep both.
10. **R2 key growth:** each save writes new timestamped thumbnail objects and does not delete old ones. A cleanup of superseded `thumb-3d-*` and `cover-flat-*` files may be needed later.
11. **Not tested at scale:** it has been used on the Computer Science sample only. Try Hindi titles, very long names, 1–3 line exam lists and books with no picture.

## Setup notes

- `sql/book_covers.sql` must exist in the target Supabase project (done for production). It is safe to re-run.
- The server actions need `ADMIN_API_SECRET` (server) and `VITE_ADMIN_API_SECRET` (client) to match, plus the existing R2 env vars used by `r2-upload`.
- Run locally with `npm run dev`; open Book Content, click **Design cover**.
